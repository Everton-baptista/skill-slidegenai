# Edit an existing presentation

Use when the user asks to update, repair, restyle, or continue a deck. Identify whether the supplied deck controls design or supplies content only. Resolve that from the request before applying a new identity.

1. Preserve the original. Inspect slide count, dimensions, master/layout usage, theme/fonts, logo variants, notes, native tables/charts, source images, and requested changes. Render representative layouts and every affected slide.
2. Use the host's native import/clone/edit operations. Prefer existing objects and stable IDs over reconstructing an entire deck. Preserve source calculations, labels, and chart data lineage when applicable.
3. Record a small change map: affected slide IDs, target objects, intended changes, and elements to preserve. Keep it internal unless requested.
4. Apply focused edits. Preserve order/count unless requested otherwise. For whole-deck restyling, intentionally remap layouts while retaining content and native evidence.
5. Render changed slides and compare before/after. Scan the whole deck for inherited theme/master effects. Check dimensions, fonts, notes, chart/table editability, and export differences.

If import loses critical native objects, preserve the source, disclose the loss, and choose a supported repair/export path. Do not silently replace a live chart with a screenshot. Native editor/import fidelity is host-dependent; never claim PowerPoint verification without actually opening it there.

For screenshot-only reconstruction, the result is an approximation: unknown fonts, hidden masters, object editability, and cropped content cannot be recovered from pixels alone. Record these gaps.
